# Учёт питания (Schautrack)

Инструменты сервера `schautrack` (в picoclaw: `mcp_schautrack_*`).

## Главные правила

1. **Ты не пересчитываешь КБЖУ на вес и не складываешь итоги сам** — это делает сервер.
   Передавай значения как в источнике (на 100 г / на штуку) и вес; итоги бери из `day_summary`.
2. **Продукт в базу — только по явной просьбе** («добавь в базу», «сохрани продукт»).
   Для записи съеденного продукт не нужен. Сам не предлагай сохранить.
3. **Не спрашивай пользователя то, что можно найти.** Нет в базе — ищи в интернете и записывай.

## Откуда брать КБЖУ (по приоритету)

1. **Цифры пользователя.** По ним ничего не ищи и не проверяй, записывай как есть.
   - По умолчанию: сначала сколько съедено, затем Б Ж У **на 100 г**, в этом порядке.
     «75г йогурта - 8 0,1 7,1» → `log_custom_entry(name="Йогурт", protein_g=8, fat_g=0.1, carbs_g=7.1, grams=75)`.
     Запятая — десятичный разделитель.
   - Уточняй только если на 100 г это невозможно (Б+Ж+У > 100 или ккал > 900)
     или пользователь сам написал «на порцию», «в пачке», «всего» (тогда `per="portion"`).
2. **Сохранённый продукт** — `log_food(items=[...])`.
3. **Интернет** — если `log_food` ответил «не найден»:
   - бренд назван → этикетка или сайт производителя; нет → USDA / Скурихин;
   - для штучного продукта возьми вес штуки из источника и передай `pieces` + `piece_grams`;
   - запиши `log_custom_entry(..., approximate=true)` — к названию добавится «~»;
   - сообщи одной строкой, что записал, какие значения на 100 г, вес штуки и источник.
   - Спрашивай пользователя, только если ничего правдоподобного не нашёл
     или источники расходятся больше чем на 30% по калориям.
4. **Штрихкод** — `lookup_barcode(code)` → `per_100g` в `log_custom_entry(per="100g", grams=...)`.
   Не найден — ищи в интернете, как в п. 3.

Не путай: «белок» продукта ≠ «белок яйца» (яичный белок — отдельный продукт, не целое яйцо).

## Пользователь сообщил, что съел

1. Разбери фразу на продукты и количество. Вес бери ровно как сказал пользователь.
   - «150г гречки» → `{"food": "гречка", "grams": 150}`
   - «2 яйца» → `{"food": "яйцо", "pieces": 2}`
   - «стакан молока» → спроси объём в мл, не угадывай.
2. Продукты с цифрами пользователя — сразу `log_custom_entry`. Остальные — `log_food(items=[...], meal="Обед")`.
   Для «вчера» передай `date="yesterday"`.
3. `log_food` вернул ошибку — ничего не записано:
   - **не найден** → этот продукт через интернет (см. выше), остальные — `log_food` повторно без него;
   - **несколько вариантов** → спроси, какой именно, и передай id (`"#12"`);
   - **нужен вес / нужны штуки** → спроси недостающее.
4. Покажи пользователю `table` из ответа.

Пример: «3 белка яиц С0 и одно целиком» →
`log_food([{"food": "яйцо С0", "pieces": 1}])` +
`log_custom_entry(name="Белок яйца С0", protein_g=11, fat_g=0.2, carbs_g=0.7, calories=52, pieces=3, piece_grams=33, approximate=true)`
→ «Белок яйца С0 нет в базе — записал по USDA: на 100 г 52 ккал, Б 11 / Ж 0.2 / У 0.7, 1 белок ≈ 33 г».

## Блюда

- Пользователь назвал ингредиенты с граммовками → каждый ингредиент отдельной записью по правилам выше.
- Только название и вес («300 г гречки с фаршем») → усреднённые значения из интернета, `approximate=true`.

## Проверка после записи

- Ответ инструмента — это то, что реально сохранено. Сверь Б/Ж/У в нём с тем, что собирался записать.
- Есть `warning` (калории не сходятся с БЖУ) или `stored_mismatch` — скажи пользователю;
  если ошибка твоя — `delete_entry(id)` и запиши заново.
- Schautrack хранит целые граммы: 0.1 г жира в порции станет 0 — это нормально, не ошибка.

## Пользователь говорит, что запись неверна

1. Сначала `day_summary` и покажи фактическую запись (название и Б/Ж/У) — не отвечай «всё верно» по памяти.
2. Если ошибка подтвердилась: `delete_entry(id)` → записать заново → показать новую `table` и `day_summary`.

## Справочник продуктов (только по явной просьбе)

- Сохранять стоит заводские продукты с фиксированным составом, которые едят часто.
- С этикетки: `add_food(name, per="100g", calories, protein_g, fat_g, carbs_g)` — значения как на упаковке, с дробями.
- Штучный: `per="piece"` и `piece_grams`. По штрихкоду: `lookup_barcode` → `add_food(per="100g", ...)`.
- Исправить: `update_food(food, ...)`.
- Удалить: `find_food` → покажи продукт → `delete_food(food)`. Записи о съеденном не пострадают.
- Чистка справочника: `find_food()` → раздели список на «оставить» (заводские продукты) и
  «удалить» (блюда, разовые позиции, дубли) → пользователь правит список → удаляй только после его «ок».

## Итоги и Obsidian

- За день: `day_summary(date)` → в заметку вставляй `table`, остаток калорий — `calories_left`.
- За неделю: `period_summary(date_from="-6", date_to="today")`.
- Не складывай числа из разных ответов сам — запроси сводку заново.
